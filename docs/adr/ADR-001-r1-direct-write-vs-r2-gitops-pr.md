# ADR-001：R1 直写 vs R2 GitOps PR 的分界

> 转录自设计文档附录 A（落地方案 T0.6）；原文出处 `AI原生K8s安全操作平台-技术方案设计文档.md` 附录 A。
> 关联不变量：I5（一切写可回滚）、I6（决策可回放）｜ 关联失败模式：F3（双写冲突）、F6（回滚失败）｜ 关联：ADR-002。

## 1. 背景

Agent 写操作走"直写集群"还是"GitOps PR"是形态级分歧。直写延迟低、交互闭环；PR 自带评审与回滚但交互断裂。风险分级 R1/R2/R3 各自走哪条通道，必须在 M2 写路径开工前拍板，否则闸门的放行语义无事实源。

## 2. 决策

R1 直写（逆操作 + 配额兜底），R2 强制 PR（ArgoCD 通道），R3 硬拒。适用范围：aegis 全部写操作的三级通道分界（对应设计文档 §4.2.3 关键取舍）。

## 3. 代价与接受

代价是 R2 用户体验断裂——Agent 不能闭环直写，须等 PR 评审合入后才生效。换来审计与回滚的确定性（评审记录与回滚由 GitOps 天然自带），接受。

## 4. 反方意见留档

若未来 M4 后做多集群，R1 也可能需统一转 PR 通道——届时重审本 ADR。

## 5. 复评触发条件

- M4 引入多集群（见反方意见留档）；或
- R2 通道（ArgoCD）的交互断裂在演示 / 使用中被证明不可接受。

命中任一即重审本决策。
